# SMIF (Serial Memory Interface) - External QSPI/Octal-SPI Flash and PSRAM Interface for Embedded C Applications

## Overview

The **SMIF (Serial Memory Interface)** driver provides a full-featured API for communicating with external SPI-based memory devices—quad-SPI NOR flash, HyperBus flash, HyperRAM, and octal-SPI PSRAM—through the MXSMIF hardware block. It enables Execute-In-Place (XIP) mode, memory-mapped read/write access, on-the-fly AES-128 encryption/decryption, DMA-assisted transfers, and automatic memory discovery via the SFDP standard.

## Features

- **XIP (Execute-In-Place):** CPU can fetch code and data directly from external flash through a 4 KB read cache, with no software intervention
- **Multi-protocol support:** SPI, Dual-SPI (DSPI), Quad-SPI (QSPI), Dual-QSPI, Octal-SPI (SDR and DDR); up to 4 external memory slots
- **On-the-fly AES-128 encryption/decryption** in XIP mode using a software-write-only key register
- **SFDP auto-detection:** Automatically reads JEDEC Serial Flash Discoverable Parameters to configure memory command sets at runtime
- **DMA-ready transfers:** TX/RX FIFOs with configurable trigger levels for CPU-free bulk data movement
- **Three-layer API:** Low-level SMIF register access (`cy_smif.h`), memory-slot abstraction (`cy_smif_memslot.h`), and QSPI Configurator-generated structures

## When to Use

- **External code storage:** Execute firmware from a large NOR flash chip when internal flash is insufficient
- **External data storage:** Store calibration tables, audio assets, or firmware images in QSPI flash with random-access reads
- **PSRAM expansion:** Add low-latency, high-density RAM via HyperRAM or Octal PSRAM in XIP mode
- **Secure field updates:** Write new firmware images to flash in MMIO mode, then boot from XIP with encryption enabled
- **Mass erase / sector management:** Erase specific sectors during wear-leveling or factory reset flows

## Prerequisites

### Hardware Requirements

- MXSMIF or SMIF IP block present on the device
- External memory device (QSPI NOR flash, HyperBus flash, PSRAM, or Octal-SPI PSRAM) connected to the SMIF pins
- Dedicated SMIF I/O pins routed in the PCB layout (CLK, CS#, DQ0–DQ7 as needed)
- For XIP: memory regions defined in the linker script mapped to the XIP base address (`CY_XIP_BASE`)

### Software Requirements

- `cy_pdl.h` (includes `cy_smif.h` and `cy_smif_memslot.h`)
- For memory-slot-level API: QSPI Configurator-generated `cycfg_qspi_memslot.h`, `cycfg_qspi_memslot.c`

### Configure in the Tool

The **QSPI Configurator** (ModusToolbox → Peripheral → Serial Memory Interface → External Tools → Launch QSPI Configurator) generates all required `cy_stc_smif_mem_config_t` and `cy_stc_smif_mem_device_cfg_t` structures.

| Parameter | Description | Typical Value | Value Explanation | Parameter Description |
|-----------|-------------|---------------|-------------------|-----------------------|
| Memory type | Protocol variant | QSPI / Octal | Match to attached device datasheet | SPI, DSPI, QSPI, Dual-QSPI, Octal-SPI |
| XIP enable (`CY_SMIF_FLAG_MEMORY_MAPPED`) | Map device into AHB address space | Enabled | Required for XIP / direct pointer reads | Bit flag in `cy_stc_smif_mem_config_t.flags` |
| Write enable (`CY_SMIF_FLAG_WRITE_ENABLE`) | Allow AHB writes in memory-mapped mode | Enabled for PSRAM | PSRAM supports write; NOR flash needs MMIO erase first | Bit flag in `cy_stc_smif_mem_config_t.flags` |
| SFDP detect (`CY_SMIF_FLAG_DETECT_SFDP`) | Auto-read JEDEC SFDP table | Enabled | Eliminates manual command-set programming | Bit flag in `cy_stc_smif_mem_config_t.flags` |
| Crypto enable (`CY_SMIF_FLAG_CRYPTO_ENABLE`) | XIP on-the-fly AES-128 | Disabled by default | Enable for encrypted code/data storage | Bit flag in `cy_stc_smif_mem_config_t.flags` |
| Deselect delay | Minimum CS# high time (bus cycles) | Device-specific | Must satisfy tCHSL in memory datasheet | `deSelectDelay` field in device config |

## Quick Start

This quick start demonstrates initializing SMIF and performing a blocking read of external QSPI flash using the memory-slot API.

**Step 1:** Run the QSPI Configurator to generate `cycfg_qspi_memslot.h/.c` for your target memory device.

**Step 2:** Enable the SMIF peripheral and configure SMIF clock (typically ≥ 50 MHz) in the Device Configurator.

**Step 3:** Connect your application code to the generated configuration structures (do **not** hand-write them).

**Step 4:** Add the following code to your `main.c`:

**Expected Outcome:** The device will initialize the external memory, erase a sector, write 256 bytes, read them back, and verify the data matches.

### Sample Code

#### Bare Metal Example (main.c)

```c
#include "cy_pdl.h"
#include "cycfg_qspi_memslot.h"   /* Generated by QSPI Configurator */

/* Context allocated in RAM */
cy_stc_smif_context_t smifContext;

/* SMIF block config from QSPI Configurator */
extern cy_stc_smif_block_config_t smifBlockConfig;

#define SMIF_HW      SMIF0
#define TIMEOUT_1MS  (1000UL)

static const cy_stc_smif_config_t smifConfig =
{
    .mode           = (uint32_t)CY_SMIF_NORMAL,
    .deselectDelay  = 7U,
    .rxClockSel     = (uint32_t)CY_SMIF_SEL_INVERTED_FEEDBACK_CLK,
    .blockEvent     = (uint32_t)CY_SMIF_BUS_ERROR,
};

int main(void)
{
    cy_en_smif_status_t status;
    uint8_t writeBuffer[256];
    uint8_t readBuffer[256];

    __enable_irq();

    /* Initialize SMIF hardware */
    status = Cy_SMIF_Init(SMIF_HW, &smifConfig, TIMEOUT_1MS, &smifContext);
    if (CY_SMIF_SUCCESS != status) { CY_ASSERT(0); }

    Cy_SMIF_Enable(SMIF_HW, &smifContext);

    /* Initialize all memory slots (configures XIP if flagged) */
    status = Cy_SMIF_MemInit(SMIF_HW, &smifBlockConfig, &smifContext);
    if (CY_SMIF_SUCCESS != status) { CY_ASSERT(0); }

    /* Prepare write data */
    for (uint32_t i = 0; i < sizeof(writeBuffer); i++) { writeBuffer[i] = (uint8_t)i; }

    cy_stc_smif_mem_config_t *memCfg = smifBlockConfig.memConfig[0];
    uint8_t addr[3] = {0x00, 0x00, 0x00};  /* Start address in external flash */

    /* Erase sector before programming (NOR flash requirement) */
    status = Cy_SMIF_MemCmdWriteEnable(SMIF_HW, memCfg, &smifContext);
    if (CY_SMIF_SUCCESS != status) { CY_ASSERT(0); }

    status = Cy_SMIF_MemEraseSector(SMIF_HW, memCfg, 0x000000UL, 4096UL, &smifContext);
    if (CY_SMIF_SUCCESS != status) { CY_ASSERT(0); }

    /* Wait for erase to complete */
    while (Cy_SMIF_MemIsBusy(SMIF_HW, memCfg, &smifContext)) {}

    /* Write data */
    status = Cy_SMIF_MemWrite(SMIF_HW, memCfg, 0x000000UL,
                               writeBuffer, sizeof(writeBuffer), &smifContext);
    if (CY_SMIF_SUCCESS != status) { CY_ASSERT(0); }

    /* Wait for program to complete */
    while (Cy_SMIF_MemIsBusy(SMIF_HW, memCfg, &smifContext)) {}

    /* Read data back */
    status = Cy_SMIF_MemRead(SMIF_HW, memCfg, 0x000000UL,
                              readBuffer, sizeof(readBuffer), &smifContext);
    if (CY_SMIF_SUCCESS != status) { CY_ASSERT(0); }

    /* Verify */
    for (uint32_t i = 0; i < sizeof(readBuffer); i++)
    {
        if (readBuffer[i] != writeBuffer[i]) { CY_ASSERT(0); }
    }

    /* Success: data verified */
    for (;;) {}
}
```

### Expected Outcome

- SMIF initializes without error
- Sector erase, program, and read complete successfully
- `readBuffer` contents match `writeBuffer` exactly (0x00, 0x01, … 0xFF)
- No assertion fires

## Troubleshooting

| Symptom | Likely Cause | Resolution |
|---------|-------------|------------|
| `Cy_SMIF_Init()` returns error | Wrong clock or pin configuration | Verify SMIF clock ≥ minimum required; check HSIOM pin routing in Device Configurator |
| `Cy_SMIF_MemIsBusy()` never returns false | Missing write-enable before erase/program | Always call `Cy_SMIF_MemCmdWriteEnable()` before every erase/program operation |
| Data read back is 0xFF (all ones) | Erase not completed; wrong address | Ensure erase completes before programming; address must be sector-aligned |
| HardFault in XIP mode during MMIO operation | CPU executing from XIP region during MMIO command | Use `Cy_SysLib_EnterCriticalSection()` / `ExitCriticalSection()` and ensure no XIP code is running |
| SMIF block stuck busy (`Cy_SMIF_BusyCheck()` always busy) | Bus contention or memory error | Toggle `CTL.ENABLED` to reset block; reconfigure; check zero-dummy-cycle SPI commands use single-bit mode |
| XIP cache stale after MMIO write | Cache not invalidated | Call `Cy_SMIF_CacheInvalidate(base, CY_SMIF_CACHE_BOTH)` before switching back to XIP |
| Octal/DDR mode not working | SMIF IP version < 2 | Octal-SPI and DDR require MXSMIF v2 or higher; verify IP version with `CY_IP_MXSMIF_VERSION` |

## Configuration Parameters Reference

| Parameter / Field | Description | Valid Values | Notes |
|-------------------|-------------|--------------|-------|
| `cy_stc_smif_config_t.mode` | SMIF operating mode | `CY_SMIF_NORMAL` | Normal (MMIO) mode; XIP is set per memory slot |
| `cy_stc_smif_config_t.deselectDelay` | CS# deselect delay (bus cycles) | 0–7 | Must satisfy memory device tCHSL; 7 is safe default |
| `cy_stc_smif_config_t.rxClockSel` | RX clock source selection | `CY_SMIF_SEL_*` variants | Use `INVERTED_FEEDBACK_CLK` for high frequencies |
| `cy_stc_smif_config_t.blockEvent` | Behavior on AHB bus error in XIP | `CY_SMIF_BUS_ERROR` / `CY_SMIF_WAIT_STATES` | `BUS_ERROR` preferred for deterministic fault handling |
| `cy_stc_smif_mem_config_t.flags` | Memory slot feature flags | `CY_SMIF_FLAG_*` bitmask | `MEMORY_MAPPED` enables XIP; `CRYPTO_ENABLE` enables AES |
| `cy_stc_smif_mem_config_t.slaveSelect` | Which CS# line drives this slot | `CY_SMIF_SLAVE_SELECT_0..3` | One slot per chip-select |
| `cy_stc_smif_mem_config_t.dataSelect` | Which data bus group to use | `CY_SMIF_DATA_SEL0..3` | Controls DQ routing |
| `cy_stc_smif_mem_config_t.baseAddress` | XIP base address of this slot | Device-specific | Must match linker script `CY_XIP_BASE` offset |
| `cy_stc_smif_mem_config_t.memMappedSize` | XIP window size (bytes) | Power-of-2, aligned | Must not exceed memory device capacity |

## Advanced Usage

### On-the-Fly XIP Encryption

Enable `CY_SMIF_FLAG_CRYPTO_ENABLE` in the memory slot flags, then set the 128-bit AES key before calling `Cy_SMIF_MemInit()`:

```c
Cy_SMIF_SetCryptoKey(SMIF_HW, key128);          /* 128-bit key */
Cy_SMIF_SetCryptoIV(SMIF_HW, iv96);             /* 96-bit IV  */
```

The XIP address is used as the AES plaintext; the resulting ciphertext is XORed with read/write data transparently. The key register is write-only from software.

### MMIO Operations While in XIP Mode (MXSMIF v3+)

With MXSMIF v3 and later, MMIO transactions are allowed while XIP is active. Use **only blocking APIs** (`Cy_SMIF_MemRead`, `Cy_SMIF_MemWrite`, `Cy_SMIF_MemEraseSector`) to guarantee completion before flash becomes available for XIP again.

### HyperBus (HyperFlash / HyperRAM)

Use `cy_smif_hb_flash.c` and `cy_smif_srf.h` for HyperBus protocol. HyperBus requires MXSMIF v2+.

### Dual-QSPI (Two Devices in Parallel)

Set `CY_SMIF_DUAL_QUAD_ENABLED` in the `cy_stc_smif_mem_config_t` to double effective bus width to 8 bits using two QSPI devices simultaneously.

### Deep Sleep and Hibernate Callbacks

Register the provided SysPm callbacks to safely suspend SMIF during low-power transitions:

```c
cy_stc_syspm_callback_t smifDeepSleepCb = {
    .callback       = &Cy_SMIF_DeepSleepCallback,
    .type           = CY_SYSPM_DEEPSLEEP,
    .callbackParams = &smifSysPm,
};
Cy_SysPm_RegisterCallback(&smifDeepSleepCb);
```
